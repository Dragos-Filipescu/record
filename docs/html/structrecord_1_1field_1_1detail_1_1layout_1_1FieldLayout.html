The aligned size of this Field set, in bytes, including tail padding.

That is, the sum of all sizeof(T), where T is F::stored_type and F is each of the Fields..., including internal padding between Ts, as well as tail padding.

This is the size that should be used when embedding Records in arrays or other contiguous structures.

Byte offsets of each field's stored value within the underlying buffer, indexed by declaration order.

That is, kOffsets[I] is the byte offset of the I-th field in Fields.... Note that fields are reordered internally to minimise padding, so offsets are not necessarily monotonically increasing.

The packed size of this Field set, in bytes.

That is, the sum of all sizeof(T), where T is F::stored_type and F is each of the Fields..., including internal padding between Ts, but excluding tail padding.

This is the size that should be used when tail padding is irrelevant, such as writing to a network buffer.

record::field::detail::layout::FieldLayout::kStorageOrder
static constexpr std::array< std::size_t, kFieldCount > kStorageOrder
The permutation mapping storage positions to declaration indices, indexed by storage position.
Definition: field.hpp:833

The same permutation as kStorageOrder, but the order of indices is reversed.

That is, kReversedStorageOrder[I] is the declaration index of the field occupying the (N - 1 - I)-th position in storage.

Note
This is strictly different from attempting to use kStorageOrder[N - 1 - I], as the indices inside it are not guaranteed to be monotonically increasing.
